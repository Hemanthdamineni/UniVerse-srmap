## 0. Follow-up: icon/glyph & accessibility pass

Narrow second pass (same day): only objectively incorrect glyph usages and verifiable a11y defects.

- `Sidebar.tsx` — `SidebarContrastText` put `aria-label` on a generic `<span>` (non-conforming, often ignored by AT) while hiding every visible char with `aria-hidden`; bare-text usages (brand line, section headers, profile info) were effectively silent to screen readers. Now the per-char split is wrapped in a single `aria-hidden` container and real text is exposed via an `sr-only` sibling. Zero visual change; contrast-char CSS/hook behavior untouched.
- `EventWorkflowPages.tsx` (My Teams) & `MyActivityPage.tsx` — `role="tablist"` containers whose buttons had no `role="tab"`/`aria-selected`. Completed the pattern: `role="tab"`, stable ids, `aria-selected`, `aria-controls`, and a `role="tabpanel"` wrapper with dynamic `aria-labelledby`.
- `AdminLmsModerationPage.tsx` — filter chips were announced as a `tablist` with no tab children or panels. Changed to `role="group"` + `aria-pressed` on each chip so active state is perceivable.
- Verified non-issues (left alone): all `<img>` elements have alt text; glyph usage (`✓ ✕ ⚠ ▼ ▶ ←`) semantically correct app-wide; ERP Curriculum/Timeline/Holidays tablists are fully implemented incl. arrow-key nav; the clickable `<div>` in dormant `EventsWidget.tsx` (superseded by CampusHubWidget, not mounted anywhere but its own test).

## 1. Missing design tokens defined (`Frontend/src/styles/base.css`)

A used-vs-defined token sweep found several CSS custom properties referenced in components
but never declared anywhere — those declarations were silently invalid (transparent pills,
inherited text colors, default browser easing). Each got a definition mapped to the closest
existing token so intent is restored without inventing new values:

| Token | Definition | Why |
|---|---|---|
| `--accent` | `var(--comp-accent)` | Used by ERP FAQ/Refund buttons, Events listing badge, Resume Builder chips, event-rules list markers; previously resolved to nothing |
| `--status-success-bg/-text/-border` | aliases of `--status-open-*` | Dashboard widgets (Events/Career/CampusHub "New"/"Open" pills) rendered with transparent backgrounds |
| `--comp-warning` | `#92400e` light / `#FFCA28` dark | Registration page warning banner border/tint/icon stroke had no tinting; matches existing `--warning` values per theme |

## 2. Dead transitions fixed (property/animation mismatch)

Two progress bars animated a property that never changes, so they snapped instead of easing:

- `RoadmapGraph.tsx` progress fill: `transition: transform …` → `width var(--duration-slow) var(--ease-spring)`
- `OrganizerDashboard.tsx` evaluation bar: `transform 0.3s ease` → `width var(--transition-base)`

Also in `RoadmapGraph.tsx`: 3× `var(--ease-out)` → `var(--ease-spring)`.
`--ease-out` was never defined, so those transitions fell back to the browser default curve.

## 3. Motion tokens adopted (same feel everywhere)

Inline `Xs ease` strings replaced with `var(--transition-fast)` (120 ms) /
`var(--transition-base)` (200 ms) on the brand spring curve `cubic-bezier(0.16, 1, 0.3, 1)`.
Duration deltas are ≤80 ms and imperceptible; easing now matches the rest of the app.

- `AdminEventsManagementPage.tsx` chart bars (2×)
- `AdminPanels.tsx` password eye toggles (2×)
- `FeePaidPage.tsx` Print button: also scoped `transition: all …` to the three properties that actually change
- `Settings.tsx` toggle: track/knob now use tokens, and the knob animates `transform: translateX(18px)` instead of animating `left` (compositor-only, Apple-style)
- `layout.css`: `.page-contrast-chip` / `.page-contrast-outline` eased `… ease` → `… var(--ease-spring)` to match their siblings
