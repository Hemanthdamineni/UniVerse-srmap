# Static prototype build

This folder receives the **production build** of the main frontend when you run the static prototype target. The app is the same React + Vite + Tailwind UI as [`../Frontend`](../Frontend), compiled with `VITE_STATIC_PROTOTYPE=true` so there is **no backend**: ERP data is read from bundled JSON fixtures, session and a few other calls are stubbed.

## Build

From the repository root:

```bash
npm --prefix Frontend run build:static
```

Output: `StaticHost/dist/` (Vite `base` is `./` so assets resolve on static hosts and subpaths).

## Serve locally

Examples:

```bash
npx --yes serve StaticHost/dist -p 4174
```

```bash
cd StaticHost/dist && python -m http.server 4174
```

Then open `http://127.0.0.1:4174/` and use in-app navigation (SPA). Use a real static server; opening `index.html` via `file://` may block `fetch()` for fixtures in some browsers.

## ERP fixtures

- **Batch payloads** (keys = ERP `pageKey` strings, values = `ErpPageResponse`-shaped objects): primary file is [`../Frontend/public/fixtures/erp-batch.json`](../Frontend/public/fixtures/erp-batch.json). Missing keys get a minimal placeholder page at runtime.
- **Session shell**: [`../Frontend/public/fixtures/session-profile.json`](../Frontend/public/fixtures/session-profile.json) (optional) merges `TableContent` into the static prototype profile when present (generated by the sync script below).

### Refresh fixtures from a live audit run

After you have captured data under `Backend/data/live-page-audit/<run>/` (via [`../Backend/scripts/audit-live-frontend-payloads.js`](../Backend/scripts/audit-live-frontend-payloads.js) / `npm --prefix Backend run audit:live-pages`), regenerate ERP fixtures and the session profile stub:

```bash
npm --prefix Frontend run fixtures:sync-audit
```

This reads the newest run’s `summary.json`, copies each page’s `processed-data-no-raw-html.json` (or `frontend-payload.json` with `rawHtml` removed) into `erp-batch.json`, and writes `session-profile.json` from the audited `profile` page.

Optional environment variables:

- `ERP_AUDIT_RUN` — timestamp folder name only, e.g. `2026-05-10T11-02-27-383Z`
- `ERP_AUDIT_RUN_DIR` — absolute or repo-relative path to a run directory that contains `summary.json`

**Privacy:** audit-derived JSON can contain real student or institutional fields. Do not commit or publish it unless your policy allows it.

### Optional manual / supplemental files

You can still add [`../Frontend/public/fixtures/erp-schema.json`](../Frontend/public/fixtures/erp-schema.json) and [`../Frontend/public/fixtures/erp-ui-hints.json`](../Frontend/public/fixtures/erp-ui-hints.json): objects keyed by `pageKey` whose values are full schema / UI hint responses. If absent, the app uses its normal fallback layout from batch `data` only.

## Other domains (LMS, events, career)

Non-ERP routes may still call `/api` directly. Coverage is **incremental**: dashboard and ERP flows are prioritized; add more stubs in the frontend (same pattern as `getEndSemesterFeedbackStatus` and admin access) or introduce MSW later if you want broad interception without touching each module.

## Normal development

Use `npm --prefix Frontend run dev` with the backend as usual. Do **not** set `VITE_STATIC_PROTOTYPE` unless you intend the fixture build.
