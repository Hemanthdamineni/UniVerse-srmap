## Changes

### 1. Session Rotation on Login (`45c9f87`)
**Severity:** HIGH (session fixation prevention)

- Added `delete()` method to both `SessionStore` and `RedisSessionStore`
- After successful ERP login, create a new session ID via `sessionStore.create()`,
  copy the authenticated data, delete the pre-auth captcha session
- Prevents attacker with pre-auth session ID from hijacking post-auth session
- Auth route test updated with mock `create()`/`delete()` methods

### 2. Rate Limiter Ordering (`45c9f87`)
**Severity:** HIGH (DoS prevention)

- Moved `express.json()` from global scope (before rate limiter)
  to `/api` scope (after rate limiter)
- Previously: attackers forced 2MB JSON parsing before being rate-limited
- Now: rate limiter rejects abusive clients before body parsing overhead

### 3. Circuit Breaker TOCTOU Race (`a3cad51`)
**Severity:** HIGH (data integrity, multi-process)

- Redis path: `WATCH`/`MULTI`/`EXEC` for atomic read-modify-write
  with single-retry fallback when optimistic lock fires
- In-memory path: safe (synchronous, no async yield between get/set)
- Prevents lost failure increments from concurrent requests near threshold

### 4. Bookmark Count Negative Guard (`a3cad51`)
**Severity:** MEDIUM (data integrity)

- Fixed `bookmarkOpportunity` decrement: `MAX(0, bookmarkCount - 1)`
- Second code path that could drive bookmarkCount negative

### 5. InMemoryErpCacheStore Expiry Sweep (`a3cad51`)
**Severity:** MEDIUM (resource leak)

- Periodic 5-minute sweep of expired entries (`setInterval` + `unref()`)
- `clear()` and `close()` methods for shutdown
- Previously: entries never read again accumulated in Map forever

### 6. Storage Quota Decrement on Resource Delete (`d10edd6`)
**Severity:** MEDIUM (data integrity)

- `deleteResource`: `updateUserStorage(-fileSize)` after soft-delete
- `restoreResource`: update quota for consistency
- Previously: totalBytes only incremented, never decremented
